# Локальная проверка пути аренды — 09.09.2026

Приоритет владельца: минимализм, понятность и дружелюбие интерфейса.
Проверка выполнена на Android API 35, emulator-5554, через Flutter UI.
Использованы только синтетические Иван/Анна, локальные PostgreSQL/Redis/MinIO.
Временный backend на 3002 и debug APK использовали тестовые версии условий
`local-smoke-2026-09-09`; ссылки example.org — заглушки, не опубликованные документы.
Production/legal/provider gates не закрывались; платные ресурсы не создавались.

## Фактический результат

- Иван выбрал чужую вещь без залога, даты, два согласия и отправил заявку через UI.
- Сообщение из чата Ивана отображается у Анны как сообщение собеседника.
- Анна подтвердила заявку: `PENDING → CONFIRMED`.
- Анна заполнила готовность вещи и выбрала фото из системной галереи;
  сохранённый акт появился у Ивана. Иван подтвердил передачу: `CONFIRMED → ACTIVE`.
- Иван создал акт возврата с фото; после галереи открылся экран этой же брони.
  Анна увидела акт и подтвердила возврат: `ACTIVE → RETURNED`.
- Временное отключение adb reverse 3002 показало в чате понятную ошибку и
  «Повторить»; после восстановления порта переписка загрузилась.
- Для отдельной заявки повтор одного HTTP-запроса с тем же X-Request-Id вернул
  тот же ID брони. Это проверка API, а не имитация двойного нажатия через UI.
- Отдельная заявка подготовлена через локальный API и отменена Анной через UI
  с подтверждением: `CANCELLED`, причина «Отклонено владельцем».

## Найдено и исправлено

1. В карточке убраны технические версии, отдельная строка валюты и выплата
   владельцу у арендатора. Комиссия сохраняется для сценария с комиссией;
   «Вы получите» показывается владельцу и скрывается для отменённой заявки.
2. Расчёт ранее скрывал ненулевой залог офлайн-объявления, после чего сервер
   отклонял заявку. Теперь отображается фактическая сумма, объяснение ограничения
   и недоступна отправка такого варианта. Серверная политика не ослаблена.
3. Проверка сессии при возврате из галереи теряла открытый imperative route.
   Router сохраняет безопасный returnTo; при недействительной сессии по-прежнему
   требуется вход. Возврат к конкретной брони проверен на эмуляторе.
4. Сброс action provider при восстановлении сессии мог пропускать создание акта
   и показывать ложный успех. Отправка ждёт завершения проверки и инициализации,
   проверяет прежнего пользователя; успех показывается только после сохранения.
5. Для `RETURNED` убран призыв выполнить недоступное завершение: текст теперь
   сообщает, что возврат подтверждён, и направляет вопросы в поддержку.

## Ограничение завершения

Офлайн-сценарий дошёл до `RETURNED`, не до `COMPLETED`. В текущем backend
автозавершение при нулевом залоге включено для FAKE_SAFE_DEAL; окончательные
правила завершения/спора остаются открыты в MVP_CHECKLIST.md §13/§14.
Не менять статус вручную и не считать полный production lifecycle проверенным.
Тестовые акты и история сохранены локально как evidence.
