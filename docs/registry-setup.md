## Что проверено локально

- Shell-синтаксис mirror и verifier корректен (`sh -n`).
- Четыре source digest в mirror соответствуют Node в backend/Dockerfile,
  PostGIS/Redis в production Compose и GlitchTip в документации.
- `make production-boundary` и `make production-boundary-test` прошли (3 теста).
- Mirror сверяет source и target digest; ошибка прерывает выполнение.
- `make production-images` требует также готовые backend/current и previous
  rollback images и production env. Сразу после создания пустого registry этот
  target ещё не может пройти: одних четырёх базовых образов недостаточно.
- Dockerfile использует отдельный pinned Dockerfile frontend из Docker Hub.
  Для будущей проверки сборки без внешнего registry понадобится его доступная
  локальная копия/зеркало наряду с Node и build-кешами. Этот сценарий не проверен.

## Первый шаг владельца — без покупки

В существующем кабинете Timeweb Cloud открыть «Kubernetes» → «Реестры
контейнеров» → «Создать»/«Добавить». Это путь к форме реестра, кластер для этой
задачи не требуется. Пока не подтверждать создание платного ресурса.

Сообщить доступный российский регион, минимальный объём и отображаемую цену.
Для проекта планируем имя `sosedi`, для реестра — `sosedi-prod` (если свободно).
Стоимость по старым статьям не использовать: проверять в текущей форме.

Документация создания описывает токен с доступом ко всем реестрам выбранного
проекта. Разделение на push/pull в ней не подтверждено. До выбора Timeweb
проверить, можно ли выдать два независимых доступа именно к этому реестру:

| Доступ | Требуемые права |
| --- | --- |
| sosedi-ci-push | Загружать и читать образы; без управления аккаунтом и billing |
| sosedi-prod-pull | Только скачивать образы; без загрузки и удаления |

Два токена с одинаковыми полными правами не заменяют это разделение.
Если форма не показывает такие права, не искать их повторно: требуется
подтверждение провайдера. Подготовленный вопрос (не отправлен):

> Можно ли для Container Registry создать независимые credentials: один для
> push/pull из CI, второй только для pull на сервере, ограниченные одним
> реестром или отдельным проектом? Где это настраивается?

## После подтверждения прав и стоимости

1. Владелец создаёт реестр в РФ и две ограниченные identity.
2. Сохраняет credentials в защищённом локальном файле/менеджере секретов;
   в чат передаёт только hostname, repository prefix, регион и названия прав.
3. Codex выполняет login с передачей секрета через stdin, запускает
   `OCI_REGISTRY_PREFIX=<фактический-prefix> make container-mirror`.
4. Codex сверяет четыре target digest и проверяет скачивание отдельным
   pull-доступом, отказ записи для него и отсутствие анонимного доступа.
5. Сборка backend, rollback image и проверка без внешнего registry выполняются
   отдельно с готовыми build-кешами и release-конфигурацией. Только фактические
   результаты позволяют закрыть соответствующие пункты checklist.
