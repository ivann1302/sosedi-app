Framework

NestJS: модульный монолит

Новая backend-фича должна оставаться простой: module, controller, service, DTO.

Что настроено глобально

app.setGlobalPrefix('api/v1');
app.useGlobalPipes(
  new ValidationPipe({
    transform: true,
    whitelist: true,
  }),
);
app.useGlobalFilters(new HttpExceptionFilter());

Что делает controller

  • Читает @Body, @Query, @Param, @CurrentUser.
  • Вызывает один метод service.
  • Возвращает ok(result).
  • Не работает напрямую с Prisma, Redis или S3.
Input

DTO, validation и transform

DTO отсекает плохой input до service. Service оставляет за собой бизнес-правила.

Пример поля объявления

@Transform(numberFromInput)
@IsNumber({ maxDecimalPlaces: 2 })
@Min(1)
@Max(1_000_000)
pricePerDay: number;

Бизнес-правила в service

  • minPrice не может быть больше maxPrice.
  • Координаты должны приходить парой.
  • Радиус геопоиска не больше 50 км.
  • Фото можно загрузить только к своему объявлению.
Response

Единый формат ответа

Controller не собирает JSON руками. Успех идет через ok(...), ошибки через Nest exceptions.

Успех

{
  "success": true,
  "data": {},
  "error": null
}

Ошибка

{
  "success": false,
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Описание ошибки"
  }
}
Security

Auth: OTP, Redis, JWT

Авторизация завязана на телефон. Redis хранит временные состояния, база хранит пользователя.

1Request OTPНормализация телефона и rate limit.
2Hash code6 цифр, bcrypt hash, TTL 5 минут.
3Verify OTPСравнение с hash и учет ошибок.
4Upsert userПользователь создается по телефону.
5Issue JWTAccess + refresh, refresh jti в Redis.

Redis ключи

  • auth:otp:code:{phone} - bcrypt hash OTP.
  • auth:otp:send:{phone} - лимит выдачи OTP.
  • auth:otp:send:device:{sha256} - лимит установки.
  • auth:otp:send:ip:{sha256} - лимит socket IP.
  • auth:otp:send:global - общий 24-часовой cap SMS.
  • auth:otp:fail:{phone} - неверные коды.
  • auth:otp:block:{phone} - блокировка ввода.
  • auth:refresh:{jti} - активный refresh token.

Guards и роли

@ApiCookieAuth('__Host-sosedi_admin')
@UseGuards(AdminSessionGuard)
@Controller('admin')
export class AdminController {}
Database

Prisma, PostgreSQL и PostGIS

Prisma покрывает обычные CRUD-запросы. PostGIS расстояния считаются через raw SQL.

Prisma

  • findMany, findFirst, findUnique.
  • create, update, upsert.
  • $transaction для связанных изменений.
  • $queryRaw для PostGIS.

PostGIS поле

location Unsupported(
  "geography(Point,4326)"
)?

Prisma видит колонку, но не управляет ей как обычным полем.

Порядок координат

ST_MakePoint(
  longitude,
  latitude
)

Это важно: сначала долгота, потом широта.

Геопоиск: при координатах используется ST_DWithin для радиуса и ST_Distance для сортировки. Максимальный радиус MVP - 50 км.
Files

S3 presigned URL, BullMQ и Sharp

Backend не проксирует тяжелые файлы. Mobile грузит файл напрямую в S3, backend подтверждает и ставит обработку в очередь.

1Presigned URLПроверка типа, размера и владельца.
2PUT to S3Mobile загружает файл напрямую.
3ConfirmСоздается запись ItemPhoto.
4BullMQ jobАсинхронная обработка фото.
5Sharp resizethumbnail 200x200 и preview 800x600.

Ограничения upload

  • Разрешены image/jpeg, image/png, image/webp.
  • Максимальный размер файла - 10 МБ.
  • KYC уходит в приватный bucket.
  • Для KYC publicUrl равен null.

MVP workflow

Как добавлять новую backend фичу

Порядок помогает не расползаться в архитектуру, которая не нужна до MVP 1.0.

Простой порядок

  • Проверить, нужна ли фича для MVP.
  • Если нужна БД - изменить schema.prisma.
  • Создать migration через make backend-prisma-migrate.
  • Создать module, controller, service, DTO.
  • Подключить module в AppModule.
  • Добавить guards, tests и релевантные проверки.

Минимальная структура

backend/src/booking/
booking.module.ts
booking.controller.ts
booking.service.ts
dto/

Не добавлять extra layers без прямой причины.

Использовать

  • Controller + DTO + Service + Prisma.
  • Prisma transaction для нескольких сущностей.
  • Redis для временного состояния.
  • BullMQ только для фоновых задач.

Не использовать до MVP 1.0

  • Microservices, CQRS, Event Sourcing, DDD.
  • GraphQL, Kafka, RabbitMQ, Elasticsearch.
  • Repository Pattern и service factories.
  • Clean Architecture и feature flags.
