# Локальные фотографии и модерация

Эта среда предназначена только для синтетических данных на компьютере
разработчика. Production-хранилище в РФ остаётся отдельным пунктом плана.

## Запуск

```sh
make infra-up
make local-storage-up
make backend-local
```

`local-storage-up` запускает отдельный Compose project `sosedi-local-storage`.
MinIO закреплён по версии и digest, API слушает только `127.0.0.1:9030`.
Скрипт создаёт `backend/.env.storage.local` с правами 600 и случайными credentials;
файл исключён из Git. Основной `backend/.env` не переписывается. Уже работающий
backend нужно остановить перед `backend-local`, чтобы освободить порт 3000.
Повторный запуск сохраняет credentials, бакеты и файлы.

Публичный бакет разрешает только чтение обработанных `items/*`.
Приватный бакет используется для исходных загрузок и требует подписи.
Сервис использует существующий S3 adapter, presigned POST, подтверждение upload
и BullMQ-обработку: отдельного fake storage API в приложении нет.
Локальный MFA encryption key также находится в этом ignored-файле.

Для Android-эмулятора/телефона использовать debug APK с
`API_BASE_URL=http://127.0.0.1:3000/api/v1`, затем:

```sh
adb -s emulator-5554 reverse tcp:3000 tcp:3000
adb -s emulator-5554 reverse tcp:9030 tcp:9030
```

Для физического телефона заменить serial. Без обоих пробросов API может работать,
а загрузка фото — нет. HTTPS production-проверки не ослабляются.

Остановка без удаления файлов:

```sh
make local-storage-down
```

Не удалять named volume, если нужны ранее загруженные тестовые фотографии.
Не использовать эти локальные credentials и HTTP-адреса для production.
